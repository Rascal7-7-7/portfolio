# 05. Portfolio v2 — Design Direction 3案

---

## 0. 前提: 現行デザインの評価

**現行デザインは「悪い」ものではない。** 全面リニューアルを出発点にすべきではない。

| 良い点（実測・目視で確認） | 根拠 |
|---|---|
| 配色設計が破綻していない | 126テキスト中122件がコントラスト合格。色数が抑制され、役割分担が明確 |
| 過剰演出がない | ネオン・Particle・3D・Glassmorphism なし。CSS transition 28箇所のみ |
| タイポ階層が機能している | h1 60px → h2 36px → h3 18px → 本文 16px → 補助 12px |
| 余白設計にゆとりがある | コンテナ `max-w-5xl` 統一、`px-6` 統一 |
| パフォーマンスが優秀 | 108KB / LCP 88ms / CLS 0 |
| レスポンシブが崩れない | 390/768/1024/1440 で横スクロールなし |

**問題はデザインではなく、(a) 載っている内容が営業用であること、(b) 作品を深掘りする構造がないこと、(c) 視覚情報（画像）がゼロであること。**

したがって3案のうち1案は「既存を活かす」案とする。

---

## 案A: Refined Dark — 既存デザインの精緻化

### Concept
現行のダークテーマ・トークン・タイポ階層を**資産として継承**し、中身を営業LPから就活ポートフォリオに載せ替える。デザイン刷新ではなく**情報の載せ替えと構造の追加**で勝負する。

### Visual Style
現行を踏襲。ミニマルなダークUI、カードベース、装飾は背景のぼかし円のみ。
追加するのは **(1) ヘッダーナビ、(2) 作品サムネイル、(3) 詳細ページのレイアウト、(4) 分野タグの色分け**。

### Color
現行トークンを継続。ただし2点修正。
- CTA: `brand-600` #0284c7 → **`brand-700` #0369a1**（白文字で AA 合格）
- 分野アクセントを追加: AI / Cloud / Security / Web を識別する4色（彩度を抑えたバリエーション）

### Typography
`next/font` で **Inter + Noto Sans JP を正しく自己ホスト**（現在は `@import` 位置ミスで未適用）。
サイズスケールは現行を継続。詳細ページ用に本文 17px / 行間 1.9 の読み物スタイルを追加。

### Layout
- 一覧: `max-w-6xl` に拡張（現行 `max-w-5xl` は1440pxで余白が過大）
- 詳細: `max-w-3xl` の1カラム読み物 + 右サイドに目次（デスクトップのみ）

### Animation
現行の transition のみを維持。`prefers-reduced-motion` に対応。**新規アニメーションは追加しない。**

### 強み
- **実装コストが最小**。既存コンポーネントの大半を再利用できる
- 現行の優秀なパフォーマンス（108KB / CLS 0）をほぼ維持できる
- 授業期間中に確実に完成させられる
- デザインの良さは既に証明済み（リスクが低い）

### 弱み
- 「作り直した感」が出ない。**授業で「改善したこと」を説明する際に見た目の変化が小さい**
- ダーク一色のため、AI / セキュリティ志向を**色や構造では表現しにくい**（テキストで語る必要がある）

### 採用向け適性: ★★★★☆
情報設計が正しくなれば十分に戦える。ただし「デザインが得意」という主張はできない。

### AI/Cloud/Security志望との相性: ★★★☆☆
ダーク＝技術系という緩い連想は働くが、能動的な表現ではない。

### 実装コスト: **小〜中**（推定: ヘッダー+IA変更 2日 / 詳細ページ 3日 / コンテンツ 継続）

## 案B: Technical Document — 技術文書としてのポートフォリオ

### Concept
**「読ませる」ことに全振りする。** 見た目の派手さを捨て、技術ドキュメント／エンジニアリングブログの様式でポートフォリオを構成する。
作品ページは「設計書」として読める密度を持ち、コードブロック・アーキテクチャ図・意思決定記録（ADR風）を主役にする。

### Visual Style
明るい背景（オフホワイト #fafafa）＋高コントラストのテキスト。
GitHub / Vercel のドキュメントサイトに近い佇まい。カード装飾は最小限、罫線とタイポグラフィで階層を作る。
サイドバーナビゲーション（デスクトップ）＋ページ内目次。

### Color
- 背景 `#fafafa` / 面 `#ffffff` / 罫線 `#e4e4e7`
- テキスト `#18181b` / 補助 `#52525b`
- アクセント1色のみ（リンクと見出しラベル）
- 分野バッジのみ色分け（AI / Cloud / Security / Network）

### Typography
本文重視。可変幅の読み物レイアウト（`max-w-[68ch]`）、等幅フォント（コード）を明示的に設計に組み込む。
日本語は Noto Sans JP、コードは JetBrains Mono など。

### Layout
- 左サイドバー（作品一覧 / セクション）＋ 本文 ＋ 右目次 の3カラム（デスクトップ）
- モバイルは1カラム + ハンバーガー

### Animation
**ほぼゼロ。** ホバーの下線表示程度。

### 強み
- **「思考を見せる」という v2 の中心目標に最も適合する**
- 技術面接官が最も読みやすい形式。Case Study との相性が完璧
- アクセシビリティとパフォーマンスを担保しやすい
- 情報量が増えても破綻しない（作品が20件でも耐える）

### 弱み
- **第一印象のインパクトが弱い**。非エンジニアの採用担当者には地味に映る
- 現行デザイン資産をほぼ捨てることになる（実装コスト大）
- 中身（文章）が薄いと**空疎さがそのまま露呈する**。書く覚悟が要る
- ライトテーマ化により、現行の完成度の高いダークUIを失う

### 採用向け適性: ★★★★☆
技術職の面接官には極めて高評価。人事の一次スクリーニングでは印象が薄い。

### AI/Cloud/Security志望との相性: ★★★★☆
「技術文書を書ける」ことがそのままセキュリティ・インフラ職の適性の証明になる。

### 実装コスト: **大**（推定: デザインシステム再構築 4日 / レイアウト 4日 / コンテンツ移行 継続）

## 案C: Systems & Signal — 領域可視化型

### Concept
**「何を作ったか」ではなく「どの技術領域に立っているか」を構造で示す。**
トップに「AI / Security / Network / Cloud / Web」の領域マップを置き、各領域に紐づく作品・学習・実験が並ぶ形にする。作品は領域を証明する証拠として配置される。

### Visual Style
ダークベース（現行を継承）＋ 領域ごとのアクセント。
Hero に**静的な領域マップ図**（SVG、アニメーションなし）を置き、領域をクリックすると該当作品へ絞り込まれる。
カードには領域バッジと「個人/チーム」「制作時期」を常時表示。

### Color
`surface` 系ダークを継承しつつ、領域ごとに5色のアクセント:
- AI: violet / Security: amber / Network: emerald / Cloud: sky / Web: slate
彩度を落として統一感を保つ（ネオンにはしない）。

### Typography
案Aと同じ（Inter + Noto Sans JP、`next/font`）。領域ラベルのみ等幅＋トラッキング広め。

### Layout
- Hero: 名前 + 一言 + 領域マップ
- Projects: 領域フィルタ付きグリッド（FEATURED 2件は横長カード、他は3カラム）
- Skills: 領域マップと同じ分類で技術を配置 → 各技術から作品へリンク

### Animation
フィルタ切替時のフェードのみ（150ms）。`prefers-reduced-motion` 対応必須。

### 強み
- **AI / セキュリティ / ネットワーク / クラウドへの志向が、テキストを読まなくても伝わる**（本監査で指摘した最大の欠落への直接的な回答）
- 作品が増えても**領域で整理されるため破綻しない**
- 「Web制作の学生」という誤認を構造的に防げる
- 既存のダークデザイン資産を活かせる

### 弱み
- **現時点の作品構成では領域が埋まらない**。AI（おうちかふぇのML推薦、ここまねのLLM連携）とWeb（MVP5本）は埋まるが、**Security / Network の作品が公開可能な形で存在しない**（`game-security-academy` は公開に課題、`brock_project` はiOS DNSで該当するが1本のみ）
- 空の領域が目立つと逆効果（「興味はあるが何もしていない」に見える）
- フィルタUIの実装とアクセシビリティ対応が追加コスト

### 採用向け適性: ★★★★☆（作品が揃えば ★★★★★）
### AI/Cloud/Security志望との相性: ★★★★★
### 実装コスト: **中〜大**（推定: 領域設計 1日 / フィルタ実装 2日 / マップSVG 1日 / 詳細ページ 3日）

## RECOMMENDED: **案A（Refined Dark）をベースに、案Cの領域可視化を段階的に取り込む**

### 選定理由

1. **本監査で判明した問題の大半は、デザインではなく情報設計と内容にある。**
   採点36点の失点は First Impression / Content / Case Study / GitHub 提示に集中しており、Visual Design は10点中7点。**デザインを作り直しても点数はほとんど動かない。**

2. **限られた期間で確実に完成させる必要がある。**
   授業期間内に「動くURL・スマホ対応・GitHub履歴・制作理由の説明」を成立させることが最優先。案Bの全面刷新は、コンテンツ執筆（Case Study 6本分）と並行すると完走リスクが高い。

3. **案Cの核心的な価値（分野志向の可視化）は、案Aの上に後から載せられる。**
   領域タグをデータモデルに最初から持たせておけば、フィルタUIと領域マップは Phase 5 以降で追加できる。**先にデータ構造だけ案C対応にしておく**のが最も効率的。

4. **案Bの価値（思考を読ませる）は、デザイン案ではなく Case Study の情報モデルとして採用できる。**
   詳細ページのレイアウトに案Bの読み物設計（`max-w-[68ch]`、目次、コードブロック、ADR風の意思決定記録）を部分的に取り込む。

### 具体的な採用方針

| 要素 | 採用元 |
|---|---|
| 全体の配色・ダークテーマ・トークン | **案A**（現行継承 + CTAコントラスト修正） |
| ヘッダー / ナビゲーション | **案A**（新規追加） |
| 作品一覧のカード設計 | **案A + 案C**（サムネイル + 領域バッジ + 個人/チーム） |
| 作品詳細ページのレイアウト | **案B**（読み物設計・目次・意思決定記録） |
| 作品データモデル | **案C**（`category: 'ai' | 'security' | 'network' | 'cloud' | 'web'` を最初から持たせる） |
| 領域フィルタ / 領域マップ | **案C**（Phase 5 以降、作品が揃ってから） |
| アニメーション | **案A**（追加しない） |

### やらないこと（明示）

- 全面リニューアル
- ライトテーマへの転換
- アニメーションライブラリ（Framer Motion 等）の追加
- 3D / Particle / Glassmorphism / Cyberpunk 表現
- 「モダンだから」という理由でのライブラリ追加
- 現行の Tailwind トークン設計の破棄
