# 01. 採用担当2分レビュー — Recruiter Review

> 前提: 採用担当者／テクニカルリクルーターが、事前情報なしにURLを開き、**2分だけ**見る。
> 評価者視点: 新卒採用担当（非エンジニア）＋ 技術面接官（エンジニア）の両方。

---

## 結論

**判定: FAIL**

このサイトは**就職活動用ポートフォリオとして機能していない**。
理由は品質が低いからではない。**用途が違うものが置かれている**ため。

現在のサイトは、取引先に開発を発注してもらうための**フリーランス営業LP**である。
- ファーストビューのCTAは「無料で相談する」
- セクション構成は「選ばれる理由」「依頼から納品までの流れ」
- 訴求は「最短5日で構築」「一人で対応します」

採用担当者が知りたいこと（誰が、何を学び、何を作り、どう考えたか）とは、**情報の向きが正反対**。
採用担当者はこのサイトを見て「この学生を採用したい」ではなく「この人に外注する案件はない」と判断して離脱する。

## 2分見た採用担当者が覚えて帰る内容（3つ以内）

1. **「Next.js で業務系Webアプリを5本作って、全部ちゃんと動く状態で公開している人」** — ここだけは強い。デモが本当に動くポートフォリオは学生では少数派。
2. **「フリーランスとして受注したいらしい」** — 採用文脈では減点。「うちに入る気がないのでは」と読まれるリスクがある。
3. **名前は覚えられない。** 書かれていないため。

### 覚えて帰らないもの（本来覚えて帰るべきだったもの）
- 氏名・所属
- AI / セキュリティ / クラウドへの関心
- 進級制作（おうちかふぇ）やチーム開発の経験
- 技術選定の判断や、詰まった箇所の解決過程

## 該当した典型的な失敗パターン

| パターン | 該当 | 補足 |
|---|---|---|
| 技術の羅列しか印象に残らない | △ 部分的に該当 | 技術タグは並ぶが、そもそも羅列すら少ない。問題は「羅列」より「技術の実像が見えない」こと |
| 何を作った人なのか分からない | ✕ 該当しない | ここは唯一成功している。5作品の内容は明確 |
| 学生であること以外の特徴がない | — 逆に該当 | **学生であることすら書かれていない**。逆方向の欠落 |

**このサイト固有の最大の失敗**: **書いた人間が誰なのか一切分からない状態で、営業をしている。**

## 視点別の所見

### 新卒採用担当（非エンジニア）の目線

> 「作ったものは多そうだけど、この人が誰で何年生なのか分からない。うちに応募してきた◯◯さんのポートフォリオかどうかも確認できない。面接で使う資料にならない。」

エントリーシートと紐づけられないポートフォリオは、採用フローの中で参照されなくなる。**氏名の欠落は運用上の致命傷**。

### 技術面接官（エンジニア）の目線

> 「5本デプロイまで持っていってるのは評価できる。ただカードに Prisma と書いてあるのに GitHub を開いたら生SQLだった。OpenAI API と書いてあるのに依存がない。ここで信用のコストが発生する。」

**実測で確認済み**: `Prisma` / `OpenAI API` / `Stripe` / `Chart.js` は5本すべての `package.json` に存在しない。
面接で「Prismaのどこが良かった?」と聞かれた瞬間に破綻する。**技術的な虚偽表示は、実装力の評価より先に信頼の問題として処理される。**

> 「あと、なぜその技術にしたのか、どこで詰まったのかが1行もない。動くものがあるのは分かったが、考えた形跡が読めない。」

### アクセシビリティ監査者の目線

> 「セマンティクスは悪くない（main / footer / article / 見出し階層は正しい）。ただし nav が存在せず、スキップリンクもなく、主要CTAのコントラストが 4.1:1 で AA 未達。リンクテキストが『デモを見る』×5、『設計・コードを見る』×6 で、リンク一覧から遷移先を判別できない。」

詳細は `04_technical_audit.md` を参照。

### 36点の内訳としての読み方

- **技術的な土台（実装・パフォーマンス・レスポンシブ）は減点が少ない。** 壊れていない。
- **失点のほぼ全ては「伝え方」と「見せ方」に集中している。** 誰が作ったか、なぜ作ったか、どう考えたかが存在しない。
- つまり **作り直しではなく、載せ替えと加筆で大きく伸びる**構造。Portfolio v2 は全面リニューアルを前提にする必要はない。

## 2分テストを PASS にするための最小条件

以下が満たされれば、同じ採点軸で **70点前後**まで到達できる（`07_implementation_backlog.md` の P0/P1 に対応）。

1. ファーストビューに **氏名・学校/学年・志向する技術領域（AI / セキュリティ / クラウド）** を置く
2. CTAを「無料で相談する」から **「作品を見る」＋「GitHub」** に差し替える
3. 作品カードの**技術タグを実装と一致させる**（Prisma / OpenAI API / Stripe / Chart.js の削除）
4. 代表作を1〜2本に**格上げして先頭に置く**（おうちかふぇ、ここまね等の追加後）
5. 各作品に **Case Study 詳細ページ**（なぜ作ったか / 詰まった点 / どう解決したか）を用意する
