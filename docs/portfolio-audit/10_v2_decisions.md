## 1. 掲載作品の再選定

### 選定基準（この順で適用）

1. **面接で自分の言葉で説明できるか** — 実装量やスター数より優先。説明できない作品は載せない
2. **公開できるか** — 秘密情報・他者の権利・クライアント許諾・チーム同意
3. **志望分野（AI / セキュリティ / ネットワーク / クラウド）を裏づけるか**
4. **開発プロセスが見えるか** — コミット履歴・PR・CI・テスト・設計文書
5. **実際に動く形で見せられるか** — URL / スクリーンショット / 動画

## 2. MVP 5本の扱い — 決定

### 現状の問題

- 5本とも Next.js + `pg` の CRUD で**内容が同質**。5枠を占有しても情報量は1枠分しかない
- 本人の評価は「適当に作ったもの」
- サイト上の技術タグが実装と不一致（`Prisma` / `OpenAI API` / `Stripe` / `Chart.js`）
- テスト0本、README なし

### 決定

| いつ | 扱い |
|---|---|
| **v2 公開時点** | **5本を1枠に集約して降格。** 一覧に「業務系Web MVP 5本（Next.js + PostgreSQL）」として1エントリ、詳細ページで5本まとめて紹介（各デモURL・GitHubは残す） |
| **改修後** | **1本だけ**を選んで作り込み、STANDARD に昇格。残り4本は集約エントリのまま |

**なぜ集約するか**: 質の高い2本（ここまね・おうちかふぇ）が、同質なMVP5枚に埋もれるのを防ぐため。
**なぜ削除しないか**: 5本とも本番稼働中で全リンク200。「動くものを5本デプロイまで持っていった」という事実自体は評価される。**量は量として、1枠で正直に見せる。**

### 改修対象の推奨: `mvp-booking-system`（予約管理）

| 理由 | |
|---|---|
| ドメインが分かりやすい | 予約・ノーショーは説明に前提知識が要らない |
| 現状が最小 | 5画面・33ファイル。作り直しのコストが最も低い |
| 伸ばす方向が明確 | **認証・入力検証・権限分離・レート制限・テスト・CI** を入れれば、そのまま**セキュリティ領域の作品**になる |
| デモが成立していない | 現在「本日の予約 0件」と表示され空に見える。相対日付のシードに直すだけで体験が改善する |

**改修の到達目標（作品として語れる状態）**
- 認証（セッション or トークン）と権限分離（スタッフ / 顧客）
- 入力検証（zod 等）とエラーハンドリング
- SQLインジェクション・XSS・CSRF 対策を**実装として説明できる**状態
- テスト（ユニット + E2E 各数本）と CI 緑
- シードデータを相対日付に変更し、デモ初期画面が埋まっている
- README（概要 / 技術 / 環境変数 / セットアップ / スクリーンショット）

> 注: これは「v2 公開後」のタスク。**v2 の公開を改修完了まで待たない。**

## 3. 志望分野のカバレッジ — 正直な現状と方針

| 領域 | 現在の裏づけ | 方針 |
|---|---|---|
| **AI** | ◎ ここまね（ローカルLLM連携）/ おうちかふぇ（LightGBM・協調フィルタ・A/Bテスト） | **主軸にする** |
| **クラウド** | ○ Neon / Vercel / GitHub Actions / ADRでのAWS・Azure比較検討 | **副軸にする**。ADRを根拠として明示 |
| **セキュリティ** | △ おうちかふぇのOTP・信頼済デバイス・CSRF実装、シークレット漏洩対応手順 | **「学習中・関心領域」として正直に置く。**改修後の booking-system で1本埋める |
| **ネットワーク** | ✕ 公開できる作品がない（NetworkShield は保留） | **作品で主張しない。**「学習中」に留める |

### 決定: 領域マップは**作らない**（当面）

`05_portfolio_v2_design.md` の案C（領域可視化）は魅力的だが、**Security / Network の枠が空のまま可視化すると「興味はあるが何もしていない」ことを強調してしまう**。

代わりに:
- 作品データの型には `categories` を**最初から持たせる**（後から可視化できるようにする）
- サイト上では **Skills の「関心を持って学んでいる領域」** として文章で示す
- 作品が揃った時点（booking-system 改修後など）でフィルタUIと領域マップを追加する

**嘘の領域マップを作らない**ことを優先する。

## 4. デザイン方針 — 決定

### 採用: 案A「Refined Dark」（既存デザインの精緻化）

**全面リニューアルはしない。** 監査結果で Visual Design は10点中7点であり、失点は情報設計と内容に集中している。デザインを作り直しても採点はほとんど動かない。

### 確定する仕様

| 項目 | 決定 |
|---|---|
| テーマ | **ダーク継続**（`surface-950` #09090b ベース）。ライトモード切替は作らない |
| カラートークン | 現行 `brand` / `surface` を継続。**CTAのみ `brand-600`(4.1:1) → `brand-700` #0369a1 に変更**（WCAG AA 適合） |
| フォント | **`next/font` で Inter + Noto Sans JP を自己ホスト**。現行の `globals.css` の `@import` は削除（CSS仕様上無効で、実測でも読み込まれていない） |
| コンテナ幅 | 一覧系を `max-w-6xl` に拡張（現行 `max-w-5xl` は1440pxで余白過大）。詳細ページは `max-w-[68ch]` |
| コンポーネント | `Button` / `Card` / `Badge` / `SectionHeader` を `cva`（導入済み）で共通化 |
| 作品カード | **サムネイル画像を必須**。作品名を最大サイズに（現在は価値メッセージの方が大きい）。個人/チームを明示 |
| 詳細ページ | 技術文書型の読み物レイアウト + デスクトップは目次 |
| アニメーション | **追加しない。** 現行の色変化のみ。`prefers-reduced-motion` に対応 |
| フォーカス | `focus-visible` でブランドカラーのアウトライン（UAデフォルトは暗背景で視認性が低い） |

### やらないこと（明示）

- ライトテーマへの転換
- アニメーションライブラリ（Framer Motion 等）の追加
- 3D / Particle / Glassmorphism / Cyberpunk / ネオン表現
- 「モダンだから」という理由でのライブラリ追加
- Tailwind トークン設計の破棄
- 現行の優秀なパフォーマンス（LCP 88ms / CLS 0 / 108KB）を犠牲にする変更

## 5. サイト構造 — 決定

```
/                     トップ（1枚で俯瞰）
 ├─ Hero              氏名 / 学校・学年 / 興味分野 / CTA「作品を見る」「GitHub」
 ├─ Featured          ここまね・おうちかふぇ（横長カード）
 ├─ About（要約）      4行 + /about へ
 ├─ Projects（抜粋）   STANDARD 3件 + /projects へ
 ├─ Skills（要約）     主要技術 + /skills へ
 └─ Contact           GitHub / メール

/projects             全作品（FEATURED / STANDARD / ARCHIVE の3階層）
/projects/[slug]      Case Study
/about                プロフィール詳細（経歴を統合）
/skills               技術一覧（各技術 → 使用作品へリンク）
/not-found            カスタム404
```

**削除するセクション**: CTA（サービスメニュー）/ Process（依頼から納品までの流れ）/ Trust（選ばれる理由）/ Footer の営業CTA
**残すセクション**: Why（なぜこの設計ができるのか）→ 「開発で大事にしていること」として About に統合

## 6. リポジトリ・URL 運用 — 決定

| 項目 | 決定 | 理由 |
|---|---|---|
| リポジトリ | **`Rascal7-7-7/portfolio-mvps` を維持** | 移行すると6コミットの履歴と Vercel 連携を失う。授業要件「GitHubで開発履歴が確認できる」に不利 |
| モノレポ構成 | **維持**（サイト本体 + MVP 5本を同居） | MVPは改修対象として手元に必要 |
| Vercel | **既存プロジェクトを維持**（GitHub Pages へ移行しない） | 授業でURL提出が必要。Next.js の動的ルートがそのまま使える |
| 公開URL | **v2完成時に Vercel プロジェクト名のみ変更**（例: `portfolio-mvps.vercel.app` → `<name>-portfolio.vercel.app`） | 「mvps」は実態と合わなくなる。ただし**変更は最後にまとめて行う**（途中で変えると共有済みリンクが切れる） |
| 独自ドメイン | **取らない** | 年間コストに対して採用上の効果が小さい。必要になってから |
| ブランチ運用 | **v2 の実装は全て Issue → Branch → PR → Merge で行う** | 授業要件に直結。現在 Issue 0 / PR 0 / ブランチ main のみで、ここが採点10点中2点 |
| README | **ルートに新規作成**（現在 GitHub API で 404） | ポートフォリオから飛んだ先が無説明の状態を解消 |
